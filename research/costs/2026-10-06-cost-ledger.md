**How to read the numbers.**
- **Times are measured** unless marked. The CSV column `notes` gives each row's `basis`:
  - `measured`: process receipts (`started_utc` + `elapsed_s`), engine stage ledgers (millisecond start and end), RunPod's own start and stop times, and pull records;
  - `log-time`: orchestrator log lines (second resolution; they can lag the real event by up to one poll interval);
  - `estimated`: derived by the method that the row states;
  - `provisional`: a pod that was still running at build time.
- **Dollars are estimates:** measured wall time × the pod's own `costPerHr` (GPU price from the pod record). Disk and storage are not in the CSV; the reconciliation (section 6) adds them.
- **A pod bills from RunPod's start time to its stop.** Each pod's rows add up to that span exactly (the script checks this). Time that no record covers is `unattributed`.
- **Price check:** every A100 pod record states `costPerHr` 1.59 (Secure Cloud, A100-SXM4-80GB). The 2 Oct pilot (RTX A5000) states 0.27 and the 4 Oct timer check 0.24.

- **Methods to time:** the protocol's per-example LoRA-gradient features (`checkpoint_gradsim`, `adam_diag_preconditioned_dot`), RepSim/DRA, TracIn-style LoRA gradients over checkpoints, and EK-FAC/SOURCE.
- **Sizing arithmetic, not a measurement:** one per-example gradient of the 73,862,144 trainable values is 295 MB in float32 (591 MB in float64). For 10,148 rows that is 3.0 TB per checkpoint in float32. So these methods need projection or on-the-fly scoring; the stored size depends on the projection dimension, which is not chosen yet.
- **Time by analogy (an estimate, not a measurement):** one forward and backward pass over every training row costs about one epoch of training. At v2 speed one epoch (init→q plus q→e1) took 21.7 min ($0.58), so a full gradient pass is of that order per checkpoint, and more if per-example gradients need smaller batches.
- **Pilot (short) runs as decision inputs:** the q checkpoint inside full jobs is measured (section 4.2), but no stand-alone pilot run has been timed, and its fixed costs (setup, preflight, evaluation) would not be shared with a full job.
- **Amortization over decisions:** cost per decision = (setup + queries × cost per query) ÷ decisions served. Neither the number of decisions per setting nor the reuse of features across decisions is recorded yet.
- **Held-out evaluation, selector seeds, human audit and API judges:** not run yet, so not costed.
- **Storage GB-months:** stopped volumes (20 GB per pod) bill until deletion, but deletion times are not recorded.
- **Larger models** (7B replication, 32B check): no runs yet; scale factors would be guesses.

## 10. Method and limits

- **Billed span:** RunPod's start (`lastStartedAt` / `createdAt`) to RunPod's 'Exited' time where a refreshed record has it, else the accepted stop request. Billing granularity is not recorded locally; seconds are used.
- **Estimated rows:** the first round-1 lead after its bootstrap (no receipts retrieved: the scoring duration is copied from the replacement lead's byte-identical run); the 2 Oct pods' end (upper bound at the SSH loss); the 2 Oct pilot's setup window; the 4 Oct timer pod's GPU type (matched by price); the local judge's span (file times).
- **Log-time rows:** pod creation wait, bundle transfer and the attempt-1 removal hosts come from orchestrator logs at second resolution, which can lag by up to one poll interval.
- **Not in the CSV:** disk and storage charges (see section 6), the account's other projects, and engineering or AI-tool time.
- **Privacy:** pod IP addresses and ports are never read into the outputs; the script refuses to write an IPv4 address.
- **Re-run:** `python3 tmp/cost-ledger/cost_ledger.py` (or `--dry-run`, or `--now` to fix the provisional end). New v2 hosts are picked up from `tmp/headroom-v2/hosts/`.
