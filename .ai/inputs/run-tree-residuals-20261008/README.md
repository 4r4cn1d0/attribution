# Run-tree residuals, 8 October 2026

This folder keeps the 40 files (72,094 bytes) of four retrieved run trees (`tmp/study-v2-20261004/retrieved`, `tmp/study-v2-20261002/retrieved-calibration`, `tmp/headroom-20261005/retrieved`, `tmp/headroom-v2/retrieved`; 5,299 files, about 3.7 GB) whose exact bytes were not already kept elsewhere, so that those trees can be moved to the Trash. A file was counted as kept when its SHA-256 is listed in the `inventory.jsonl` of a private backup release (`backup-2026-10-03`, which also lists the members of the `backup-2026-10-02` calibration archives, `backup-2026-10-04`, `backup-2026-10-05`, `backup-2026-10-06-headroom-v2`; each inventory matched its release `SHA256SUMS`), when its `git hash-object` id is reachable from a local or `origin` branch, or when it is a verbatim file of `research/costs/receipts-snapshot/` (the `steps.jsonl` files that snapshot cuts all have their original hash in a release inventory). The two 295.5 MB a0 e3 `adapter.safetensors` files of `headroom-20261005` are not in that release's `inventory.jsonl` but are listed by SHA-256 in its `a0-adapters-manifest.json` asset (committed as `backups/2026-10-05/a0-adapters-manifest.json`; GitHub's asset digest equals the committed file's SHA-256, and the manifest's `tar_sha256` equals the digest of the `headroom-round1-a0-e3-adapters.tar` asset), so they were counted as kept and not copied. The residual files are the per-host `dev-matrix-002/registry.jsonl` files (13), the calibration hosts' `archive-receipt.json` and `verification.json` (10), and the per-unit `verified.jsonl` files of both headroom runs (17); none of their paths appears in any inventory. Each file keeps its path relative to `tmp/` (the leading `tmp/` is dropped because `.gitignore` ignores every directory named `tmp`), and `index.jsonl` gives its tree, path in the tree, size, SHA-256 and `archive_path`. A secret scan of all 40 files (Hugging Face, RunPod and GitHub tokens, private-key blocks, SSH public keys, IPv4 addresses, and the words key, secret, password, bearer, authorization, known_hosts and PUBLIC_KEY) found nothing, so no file or field was excluded.
