## 2. Alternatives and why

1. **Keep `plan_tool.py` whole and add a block-0 route** (chosen) vs. rewrite a small 7-8B plan tool. The copy keeps every stage-1 function (record_done, defer, requeue, confirm_stopped, moved_hosts, block_complete, the seal's helpers) importable, so `finisher.py`, `seal.py`, `host.py`, `launch.py` and `orchestrate.py` import unchanged and the next stages port those functions with their 1B assumptions visible in one diff. Cost: 4,663 lines, most unreachable from block 0; the module-level 1B references needed four None-safe edits. A rewrite would have been smaller but would have made the launch and runner stages re-create the requeue path (ruling 11's fallback) from scratch.
2. **The family from the folder name** (KD7) with an optional `kit-family.json` that must agree (chosen) vs. an explicit `--family` on every command vs. a file alone. The folder name is the KD7 contract and cannot be forgotten; the file is needed on the pod (the pod's folder is not a KD7 name) and pack_setup writes it into the setup tar. `--family` exists on pack_setup only as a check (it must equal the copy's).
3. **The sealed set as the one edit source for block 0** (chosen) vs. keeping MAN1 as a source. MAN1 is the 1B stage-1 commitments manifest (A1's 1B edit); no 7-8B edit lives there. The edit file's `manifest_sha256` is read (one key) so an edit on the other prepared set refuses (P78 §2.3 condition 3); its remove list is never read or printed.
4. **The fixture = the a0-1101 side unit's preflight `verification.json`** (chosen) vs. the basis file vs. no fixture. The plan T4 names "the fixture path" in the constants block; the stage-1 plan records the pod-side typical case in `plan.json["fixture"]`; the a0-1101 side unit is P78 §2.1's reference unit for the environment rule, and its verification.json carries the family's recipe, manifest and training identity, so the fixture doubles as a per-family identity check (M: `fixture()` refuses a file of the other family). Caps never read it (KD1).
5. **N's need as the funding check** (both families, $56.06) (chosen) vs. this pod's need alone ($27.16 / $34.86). N is one launch of two pods (ruling 11); the user funds the block, not a pod; each family's copy takes the same block-0 record (the stage-1 kit's "one funding record per group" rule). Both figures are printed.
6. **D1 by the code pin** (RECIPE_BQI; A1's pattern) as the brief says, not the doc fix (the re-verifier's option (a)).
7. **A test-local synthetic Llama sealed set** in the World, with the manifest form of Gate B's set (`files[{role "edit", family "R", draw, arm, path, sha256}]`) (I: the parallel round builds the Llama set "like SEAL", Part 1 §3.1). If the merged set's manifest differs in form, `plan_tool.manifest()` and `pack_setup.sealed_set()` refuse ("lists no R draw(s) at role 'edit'"), which is the safe failure; section 6 names the check for the lead.
8. **No port of the 1B-block tests** (section 8) rather than hundreds of skips: they test logic the copy refuses by design (`BLOCKS == ("0",)`); one test holds the refusal for every 1B block.
