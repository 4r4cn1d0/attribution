### D1. `states_tool.py check HOST e1` refuses the probe pod's tree (the records: the state rule)

The probe pod's `round1/` holds two units: the untuned unit `1101-a0-init-a1` (`run-one --target init`, `setup/job_runner_probe.py:47-50`), which saves `states/init/` only (R: `experiments/safety_selection/runner.py:441-447`, the only `save_state` call on the `previous is None` path before the `for name in names[...]` loop, which is empty for target init), and the e1 unit `1101-a0-e1-a1`. So the README's step 3 (`README.md:49`) and the O3C report's "states verified: 2 units" (§5) can never happen on the probe pod; the check only works on a fine-tune-only reuse pod (one unit). The builder's test (`tests/test_family_probe_olmo3.py:449-466`) builds a one-unit tree, so it did not see it.
- **Reproduction (M, exit 2).** `<scratch>/verify-O3C/d1/`: a copy of `states_tool.py`; `retrieved/olmo3-7b-1101/tree/round1/1101-a0-init-a1/COMPLETE.json` listing `states/init/state.json`, `states/init/adapter.safetensors`, `job.json`; `…/1101-a0-e1-a1/COMPLETE.json` listing `states/init/*`, `states/e1/state.json`, `states/e1/adapter.safetensors`, `job.json`; `retrieved/olmo3-7b-1101/states-e1-20261105T000000Z.tar` holding the e1 unit's two `states/e1/` files (what `ls -d round1/*/states/e1 | tar -cf - -T -` ships). `python3.11 -B states_tool.py check olmo3-7b-1101 e1` → stderr `1101-a0-init-a1: COMPLETE.json lists no states/e1/ file`, **exit 2**.
