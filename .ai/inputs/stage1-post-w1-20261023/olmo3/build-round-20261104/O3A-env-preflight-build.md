## Design

### The comparison rule (B3; CM D-O4; MC §6.2 B3)

- **Rows.** The seven unused `<|extra_id_N|>` rows: `<|extra_id_0|>` 100256 and `<|extra_id_1..6|>` 100270-100275. Confirmed from the cached tokenizer (F0): each is a plain added token (not special), none is in the chat template, none is a chat token or the pad. `extra_id_rows(tokenizer, n_rows, chat_ids, pad_id)` re-confirms all of this on every run and refuses otherwise (a fixed message per case). It also refuses a model with more rows than tokens (then the family rule applies; OLMo 3 has 100,278 for 100,278). Its signature equals the family `comparison_rows`, so `main` differs by the name alone.
- **Rule.** `chat_rows_report_cosine` runs the family `chat_rows_report` (the engine's `token_row_report` per side, which already gives each chat row's largest cosine to any comparison row) and then decides: a chat row is distinct when its largest cosine to any comparison row is at most COSINE_SAME = 0.99 (an angle of at least 8.1 degrees), on the input and the output side; `chat_rows_distinct` is true when every chat row is distinct on both sides. The comparison rows must be a clean reference: their smallest pairwise cosine is at least 0.99 (unused rows point one way); otherwise `chat_rows_distinct` is null with a note, and the family verdict refuses the recipe, as it does with no rows. The family's bit-identity result is recorded as `bit_identical_rule`, never used for the verdict. A distance (L2 to the nearest comparison row) is recorded per chat row for the lead's reading, not used.
- **Why 0.99.** Untrained rows are parallel without being bit-identical: the 5 Oct read of OLMo 3 7B Base found cosine 1.000 between the chat rows and the unused rows (CM:126 citing research/experiments/2026-10-05-headroom-v2-workplan.md:19). Trained chat rows in the recorded fixtures reach at most 0.87 (Llama-3.1-8B's output head: 0.74-0.87 over its four chat rows; OLMo-2-7B's output `<|endoftext|>` 0.46; OLMo-2-1B 0.22; every input side at most 0.04; read from the expected-fixture-probe.json records in the main checkout's tmp/family-probe-* folders). A bfloat16 rounding of a scaled copy moves a cosine by about 1e-5. So 0.99 sits 0.12 above the highest trained value seen and 0.01 below the parallel case; a chat row that kept over 99 percent of the untrained direction reads "the same way", the conservative side.
- **Where it runs.** `main` is the family `main` copied with four line changes (the kind string plus the rule record, the architecture refusal, the two comparison lines); `test_main_is_the_family_main_with_the_comparison_step_replaced` pins the unified diff of the two function sources to exactly those lines, so any later change to the family main shows up as a failing test here. Everything else (chat tokens, tokenizer check, memory preflight, resume check, batch checks, guard, full-length check, timed sample, BOS record, verdict, early stops, cap projection, `_finish`) is imported from the family preflight.
- **Refusals.** A recipe whose architecture is not `Olmo3ForCausalLM`: exit 2, fixed message, before any folder is made. A row that cannot be confirmed: `Olmo3PreflightError` inside the run, so the family's error path writes error.txt and partial-verification.json and exits 1, as every preflight error does. The `--rule-check` form refuses a config that is not OLMo 3's (exit 2) and an existing out folder (the engine's `create_run_dir`).
- **Report fields added.** `script_sha256` is the new file's hash; `comparison_rule` holds the rows, the threshold, the rule text and `family_script_sha256` (the family preflight's hash). Output is the engine's `write_json` (canonical JSON, atomic) into a folder the engine creates exclusively.
- **The CPU form.** `--rule-check --config CONFIG_JSON --tokenizer SNAPSHOT --out FOLDER --end --stop --stop --pad --header` (the codec flags as scripts/family_codec_check.py takes them): a random `Olmo3ForCausalLM` from the config folder, the engine's LoRA wrapping and seeded adapter, the codec and the assistant-header check from the snapshot, `derive_chat_tokens`, `effective_embedding_weights`, the rows and the rule; writes rule-check.json only (no verification.json, no COMPLETE.json). Random rows are not parallel, so its verdict is null by rule; the tests show True and False on the same tiny model by setting rows in place.

## Rejected alternatives

1. Monkeypatching `cuda_preflight_family.comparison_rows` and `chat_rows_report` and calling its `main`. Shorter, but implicit; the kit's fixture would record the family script's hash as `script_sha256`; and a report field cannot be added without patching `_finish` too. The repository's precedent is the family preflight itself, which copied the kill-test preflight's main with its changes. Chosen: the copy, pinned by a diff test.
2. Bit identity (the family rule) on the extra_id rows. It cannot see parallel untrained rows (CM:126; the Base read gave cosine 1.000 with distinct bytes). Rejected.
3. A distance threshold instead of cosine. Row norms differ between untrained rows (OLMo-2's padding rows had median norm 0.89 against 9.9 for ordinary rows, Llama's reserved input rows about 1e-21), so a distance needs a scale per model; cosine does not. Chosen: cosine for the verdict, the distance recorded for reading.
4. A lower threshold (for example 0.9). It would still separate the recorded cases, but with less margin above 0.87, the highest trained value seen; 0.99 keeps both margins. The lead may set another value: it is one constant, COSINE_SAME, named in the report of every run.
5. Making the "comparison rows parallel" check a verdict False instead of null. Null matches the family's semantics ("nothing to compare with"), and the lead reads the record either way. Chosen: null with a note.
6. A full CPU run of the A100 preflight on the tiny model. The family main hard-codes "cuda" and the real loaders refuse CPU by design; a device switch would be a new code path that never runs on the pod. Chosen: the `--rule-check` form that exercises the new path only.
7. Putting the tests under experiments/safety_selection/tests/. Those are engine files (not editable here, and the stage-1 pack refuses uncommitted files there). Chosen: scripts/tests/ with the scripts/stage1/tests conftest pattern.
